# Obsidian knowledge

Generate a project note plus selective reusable Problem and Pattern notes. Do not make one note per event. A Problem needs a meaningful, reusable failure/root cause; a Pattern needs a generalizable decision or lesson. Verify links and frontmatter after export.

Config lives in `~/.codex/project-knowledge-pipeline/config.json` with `obsidian.enabled`, `vault_path`, and `base_folder`. If no unambiguous vault is configured, keep local generated notes and report that vault export is pending. Avoid overwriting unrelated vault notes.
